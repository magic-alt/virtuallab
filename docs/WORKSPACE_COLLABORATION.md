# 跨仓库协作

VirtualLab 允许一个工作区的 Codex 对照其他本地仓库的代码。每次执行仍有一个主仓库和主 Worktree；关联仓库提供参考代码。项目名称、目录和协议由用户选择，应用不绑定任何具体设备或工程。

## 上位机与固件如何一起排查

1. 在工程仓库中分别添加上位机与固件的本地 Git 仓库。
2. 选中上位机要修改的 Worktree，在 Overview 的「协作仓库」中勾选固件仓库。
3. 选择固件实际参与联调的 Worktree，核对其路径。不要仅凭仓库名称假定它就是当前设备使用的版本。
4. 打开 Terminal，点击 Start Codex；或进入 Agents Hub 的工作区会话，检查同一份关联选择后发送任务。
5. 描述要对照的接口。例如：「对照关联固件的对象字典与命令处理，修复本仓库速度单位换算；列出两端当前约定以及验证结果。」
6. 在主仓库的 Changes 中检查修改。若固件也需要改变，把这些建议放入固件自己的任务，由固件 Worktree 完成修改与验证。
7. 对双向协作，在固件仓库中同样选择上位机作为参考。两个任务各自保留提交、运行结果和责任范围。

## 三个入口的行为

| 入口 | 关联信息从哪里来 | 设置变化何时生效 |
| --- | --- | --- |
| 工程仓库 → Start Codex | 当前主仓库保存的关联列表 | 新建 Codex 终端时 |
| Agents Hub → 工作区会话 | 主仓库保存的列表，连接时固定到会话 | Stop runtime 后重新连接 |
| Agents Hub → Agent 任务 | 创建时写入任务记录的列表 | 每个新任务；已接受任务的重试继续使用原列表 |

每个关联项明确保存仓库根目录和实际读取的 Worktree，最多八项。切换侧栏、换页面或在另一仓库选中不同 Worktree，不会改变已有选择。普通 Shell 终端仍按原方式启动；手动运行其他工具时，需要自行提供其上下文。

## 权限与生命周期

关联目录用于读取代码，Codex 的主 cwd 和允许写入的工作区继续指向主 Worktree。VirtualLab 不为关联仓库添加 `--add-dir` 或额外写入根目录。原生端验证路径存在、Git Worktree 归属和实际目录身份；错误的目录、重复引用和与主写入目录重叠的引用会被拒绝。

运行中的 provider 保留关联目录的使用记录。如果 VirtualLab 提示关联仓库正在使用，应先停止引用它的会话/终端，再移除仓库或 Worktree。已有终端和会话不会因配置变化被自动终止。

Windows/macOS/Linux 的文件权限以及 Codex 管理策略仍然生效。遇到受限读取时应处理具体权限或路径问题；应用不会自动切换成全盘访问。未接入同等上下文能力的 CLI provider 会明确拒绝非空关联列表。

未选择关联仓库时，Codex 终端沿用用户已有的权限配置。选择关联仓库后，原生端先检查有效配置；已有只读模式仍保持只读。当前无法完整保留的命名/自定义权限 Profile 会明确报错，用户需要选择兼容的配置后再启动。检查配置不会发送模型任务。

## 结果如何理解

引用的是所选 Worktree 的当前本地内容，包含尚未提交的修改。它适合联调时对照两端实现，但不是对多个仓库同时拍下的不可变快照。其他进程可能继续编辑这些文件。

一个任务的正式验证、候选提交和审查仍覆盖自己的主仓库。Agent 阅读过固件源码，不代表设备已烧录该版本，也不代表硬件联调通过。需要复现时应记录两端实际提交、未提交变更、构建结果和设备版本。

关联设置在本地持久化。删除仓库注册会移除相关配置；已创建任务仍保留原始引用以便审查。关联目录暂时离线不会阻止历史任务加载，但新的执行会明确报告不可用路径。

## 验证参考

- 原生：临时真实 Git 仓库/Worktree 的归属校验、路径别名、重复/重叠目录、Unicode/空格、生命周期保留。
- 会话：关联列表透传、运行中拒绝静默改配、主写入范围不扩大。
- 终端：结构化启动参数与执行文件偏好；普通 Shell、通知、停止和多 Worktree 留存继续工作。
- 任务：旧记录兼容、关联快照不可变、目录离线时的历史恢复、幂等启动重试。
- UI：选择持久化、固定 Worktree、移除仓库、任务/会话/终端三个入口。

Codex 官方语义参考：[CLI 参数](https://developers.openai.com/codex/cli/reference)、[App-server](https://developers.openai.com/codex/app-server)、[沙箱](https://developers.openai.com/codex/sandbox)。
