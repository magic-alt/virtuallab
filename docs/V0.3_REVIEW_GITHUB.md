# V0.3 Review and GitHub implementation contract

**Current:** V0.1/V0.2 prerequisites are closed; typed diff + Monaco are on `main`. Local drafts and GitHub integration are implemented on `feat/v0.3-review-drafts-github`. Tracking issue: #4.

V0.3 turns a workspace into a local review lane. It does **not** add agent harnesses and it does not broaden the destructive-operation boundary.

## Product invariant

```text
Repository
  └─ Workspace / worktree
      ├─ Changes
      ├─ Diff / review
      ├─ Terminal / Run / Checks
      └─ GitHub PR / issue context
```

The workspace continues to own execution and review context. GitHub is an adapter attached to that workspace.

## Phase 1 — typed local diff

**Status: implemented in the first V0.3 development slice.** The native adapter is read-only, runs off the UI thread, validates workspace membership/path/base refs, bounds output to 512 KiB / 12,000 lines, detects binary diffs, and feeds a temporary plain-text review surface. Monaco replaces only the renderer in Phase 2; the diff contract remains stable.

Add a narrow Rust Git command for read-only diff retrieval. The request must be structured rather than a free-form Git command.

Suggested request model:

```ts
type DiffMode = "worktree" | "index" | "base";

interface DiffRequest {
  repositoryRoot: string;
  workspaceRoot: string;
  path?: string;
  mode: DiffMode;
  baseRef?: string;
}
```

The response should carry file identity/status plus patch text and flags for binary/truncated content. Define explicit byte/line limits before Monaco rendering.

Acceptance:

- modified/added/deleted/renamed files
- staged and unstaged views
- paths with spaces/Unicode
- binary file detection
- bounded output for very large diffs
- no Git write operation

## Phase 2 — Monaco review surface

**Status: implemented.** Monaco is bundled locally (no CDN), lazy-loaded from the Changes tab, and renders bounded native original/modified content in read-only unified or side-by-side layouts. Line selection can create local review drafts, drafts persist per workspace, and active drafts are marked stale after HEAD changes.

The Changes tab becomes file selection plus a read-only Monaco diff/editor surface.

Required UX:

- file list remains available while reviewing
- unified/side-by-side preference is local UI state
- loading/error/empty/binary/truncated states are explicit
- selecting a line can create a **local review draft**
- review drafts persist with the workspace context
- changing HEAD marks affected review state stale rather than silently reusing it

V0.3 does not need to modify source files through Monaco.

## Phase 3 — GitHub adapter

**Status: implemented on `feat/v0.3-review-drafts-github`.** The native adapter detects `gh`, reuses existing local authentication, resolves the GitHub repository from origin, loads PR/issue context, changed files and check summaries, and exposes review-comment posting as a separate typed mutation. Missing `gh`, missing auth, non-GitHub remotes and offline/auth probe failures fall back to local-only mode without disabling diff/review.

Start behind one typed adapter interface. The baseline implementation should use the local `gh` CLI when available so VirtualLab can reuse the developer's existing GitHub authentication without storing a token itself.

Read capabilities:

- detect `gh` and authentication state
- resolve repository owner/name from origin
- PR number/title/state/base/head
- changed files
- check/status summary
- issue metadata

The UI must retain full local diff/review functionality when `gh` is missing, unauthenticated or offline.

Network writes are separate methods and must have an explicit user gesture. Posting a review comment is allowed only after the user selects the draft and confirms the action. Merge, force-push and release actions remain out of scope.

## Phase 4 — issue/review workflow

Target workflow:

```text
Issue / PR
  → create/select isolated worktree
  → inspect changes
  → review locally
  → fix using terminal/editor/external tools
  → refresh
  → re-review
  → optionally post selected review drafts
```

Persist enough state to restore the active PR/issue reference and local review drafts per workspace.

## Architecture boundaries

- React components call typed wrappers under `src/lib/`.
- Native Git/`gh` process access stays in Rust.
- Never expose an arbitrary shell command string.
- Treat GitHub metadata as optional external context, not the owner of workspace state.
- Read-only capability is the default.
- No merge, reset, clean, force push or release command in V0.3.

## Suggested implementation order

1. Rust diff request/response + fixtures/tests.
2. Changes file selection and Monaco read-only diff.
3. Local review-draft store and stale-state handling.
4. `gh` capability detection + read-only PR/issue metadata.
5. PR/checks UI.
6. issue → workspace flow.
7. explicit review-comment posting.
8. cross-platform acceptance and documentation closeout.
