# V0.4 → V0.5 agent foundation

This contract defines the first bridge between the V0.4 verification control plane and V0.5 agent harnesses.

The invariant remains:

> **Agent belongs to Workspace. Workspace does not belong to Agent.**

## Scope

This slice implements the first three priorities:

1. `HarnessAdapter` + `CodexAppServerAdapter`
2. durable one-workspace ↔ one-Codex-thread binding
3. `VerificationProfile` + `EvidenceManifest` contracts

It deliberately does **not** implement autonomous hardware access, release actions, a custom agent loop, or a full agent chat UI.

## Architecture

```text
Repository
  └─ Workspace / worktree
      ├─ terminal + process execution
      ├─ diff / review / GitHub
      ├─ verification profile
      ├─ evidence manifest
      └─ agent binding
           │
           ▼
      HarnessAdapter
           │
           ▼
   CodexAppServerAdapter
           │ Tauri typed commands
           ▼
   Rust AgentManager
           │ stdio JSON-RPC
           ▼
      codex app-server
           │
           ├─ initialize / initialized
           ├─ thread/start
           ├─ thread/resume
           ├─ turn/start
           ├─ turn/steer
           └─ turn/interrupt
```

VirtualLab does not scrape Codex terminal output and does not reimplement the Codex agent loop.

## Workspace ↔ thread ownership

A persisted binding contains:

- workspace root
- harness kind
- Codex thread id
- creation/update timestamps

The persisted binding is durable; the app-server process is ephemeral. On desktop restart, VirtualLab can start a new app-server process and resume the saved thread by id.

Only one active Codex thread may be attached to a workspace runtime at a time. Attaching a different thread requires stopping the current runtime first.

## Codex safety baseline

Until the VirtualLab approval/hardware broker is implemented, Codex threads start or resume with:

- `sandbox = "workspace-write"`
- `approvalPolicy = "never"`

This is intentional fail-closed behavior. Workspace-local edits can proceed, while commands that require approval/elevation fail rather than bypassing VirtualLab.

Stopping a VirtualLab agent session kills the local app-server process; it does not archive or delete the durable Codex thread.

## Structured events

The Rust adapter emits `agent://event` payloads. Codex app-server notifications are passed as structured JSON with extracted `threadId` / `turnId` where present.

The UI must consume these events as typed state, not parse terminal text.

## Verification profile

A profile is a versioned set of gates. The first contract supports:

- gate kinds: build, unit, HIL, hardware, soak, evidence
- required vs optional gates
- human-approval marker
- structured process executors (`program` + `args`, never a shell command string)
- future HIL/hardware adapter executors

The profile contract does not yet execute gates; the runner belongs to the next V0.4 slice.

## Evidence manifest

An evidence manifest binds a verification run to:

- profile id
- workspace root
- repository HEAD
- gate/check results
- artifact references
- optional firmware / bitstream / DUT / hardware revision metadata

A release verdict must eventually derive from evidence. Agent prose is not release evidence.
